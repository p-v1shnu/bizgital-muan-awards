# การถูกค้นเจอ — Google และ AI

> ทำเมื่อ 15 ส.ค. 2026 · เจ้าของโปรเจกต์ถามว่า "อยากให้ข้อมูลกรรมการ ผู้เข้าแข่งขัน
> และผู้ชนะ ติด SEO และติดการค้นหาจาก AI ให้ได้มากที่สุด"

เอกสารนี้บอกว่า **ทำอะไรไปแล้ว ทำไม และอะไรที่จงใจไม่ทำ**

---

## 1. โจทย์ที่ต่างจากเว็บทั่วไป

เว็บนี้เขียนด้วย**อักษรลาวล้วน** ซึ่งเปลี่ยนน้ำหนักของงาน SEO ไปพอสมควร

- คนถาม AI เป็นภาษาอังกฤษ — *"who won Muan Awards 2025"* — แต่ทั้งหน้าไม่มีอักษรละตินให้จับ
- ชื่อคนลาวสะกดได้หลายแบบ · ระบบเราถึงมีฟีเจอร์รวมชื่อ (PRD §7.2) อยู่แล้ว
- เนื้อหาที่มีค่าที่สุด (ใครชนะสาขาอะไรปีไหน) เดิมสื่อผ่าน **layout** คือแถวในตาราง
  ซึ่งเครื่องอ่านได้ไม่ดีเท่าประโยคหรือข้อมูลที่มีโครงสร้าง

ข่าวดีคือของพื้นฐานผ่านหมดตั้งแต่ต้น: ชื่อนอมินีทุกคน**อยู่ใน HTML จริง**ไม่ได้ซ่อนหลัง
JavaScript (ตรวจแล้ว 24 จุดในหน้าเดียว) ตารางที่พับใช้ `<details>` ล้วน · AI crawler
ส่วนใหญ่ไม่รัน JavaScript ตรงนี้จึงไม่เสียเปล่า

## 2. รูปภาพ — `alt` ไม่ใช่ชื่อไฟล์

**เดิม:** รูปคนทุกรูปบนเว็บไม่มีคำบรรยายเลย `Avatar` ฮาร์ดโค้ด `alt=""` ไว้
แปลว่ารูปกรรมการ รูปผู้ชนะ รูปโปรไฟล์ครีเอเตอร์ **มองไม่เห็นทั้งใน Google Images
และใน AI crawler** (โลโก้สปอนเซอร์มี `alt` อยู่แล้ว — pattern ถูก แค่ไม่ได้ใช้กับรูปคน)

**กติกาที่ใช้ตอนนี้**

| รูปอยู่ตรงไหน | `alt` | เหตุผล |
|---|---|---|
| ในลิงก์ที่มีชื่อคนเป็นข้อความอยู่แล้ว (ตารางผู้ชนะ, การ์ดนอมินี) | ว่าง | ใส่ไปก็ทำให้ screen reader อ่านชื่อซ้ำสองรอบ |
| ยืนเดี่ยว (รูปโปรไฟล์บนหน้าครีเอเตอร์, การ์ดกรรมการ, hero ของปี) | ชื่อคน / ชื่องาน | เป็นตัวรูปเอง ไม่ใช่ของประดับข้างลิงก์ |

มีเทสต์กวาดทุกหน้าคุมกติกานี้ไว้ — `every picture that stands alone says what it is`
พิสูจน์แล้วว่าถ้าเอา `alt` ออกจากรูปโปรไฟล์ เทสต์แดงจริง

### ทำไมไม่เปลี่ยนชื่อไฟล์รูป

เจ้าของโปรเจกต์เสนอให้ระบบ rename ไฟล์รูปตามชื่อคนเวลาแก้ชื่อ — **ตัดสินใจว่าไม่ทำ**

1. ปัญหาที่กลัวไม่มีอยู่จริง — ระบบไม่เคยใช้ชื่อไฟล์ที่ทีมอัปโหลดมาเลย
   (`storage.service.ts` ตั้งเป็น `<folder>/<uuid>.<ext>` เสมอ) `IMG_4471.jpg` ไม่เคยไปถึงเว็บ
2. object storage ไม่มีคำสั่ง rename — ต้อง copy แล้ว delete · ถ้าครึ่งทางล้มเหลว
   ผลคือ**รูปหายทั้งเว็บ**หรือไฟล์ค้างซ้ำ
3. URL เก่าที่ Facebook scrape ไปแล้วจะตาย โพสต์ที่เคยแชร์กลายเป็นการ์ดไม่มีรูป
4. ระบบออกแบบให้**แก้ชื่อคนได้บ่อย** (§7.2) ทุกครั้งที่แก้ก็ต้องขยับไฟล์
5. ชื่อไฟล์เป็นสัญญาณที่อ่อนกว่า `alt` + ข้อความรอบรูป + title มาก

> ถ้าจะเอาจริง ทางที่ปลอดภัยคือตั้งชื่อให้ดี**ตอนอัปโหลดครั้งแรก** แล้วไม่ขยับอีกเลย
> — ได้ประโยชน์เท่ากัน ความเสี่ยงเป็นศูนย์ แต่ impact ต่ำ ยังไม่ได้ทำ

## 3. Structured data (JSON-LD)

**เดิมมี 3 หน้า** หน้าแรก (Organization) · หน้าปี (Event) · หน้าครีเอเตอร์ (Person)

| หน้า | ตอนนี้มีอะไร |
|---|---|
| หน้าแรก | Organization |
| หน้าปี | Event (+ สปอนเซอร์, ชื่อภาษาอังกฤษของปี) · BreadcrumbList · **ItemList คณะกรรมการ** |
| หน้าสาขา | **ItemList นอมินีทุกคน** + ระบุผู้ชนะทั้งที่ `mainEntity` และบนตัวคน · BreadcrumbList |
| หน้าครีเอเตอร์ | Person + **`sameAs`** + `award` + `subjectOf` ทุกปีที่เข้าชิง · BreadcrumbList |
| `/winners` | CollectionPage + ItemList ทุกปี |

**`sameAs` คือชิ้นที่สำคัญที่สุด** ทีมกรอกลิงก์ Facebook/TikTok/YouTube ของครีเอเตอร์
ไว้ในหลังบ้านอยู่แล้ว และหน้าเว็บก็แสดงลิงก์นั้นอยู่แล้ว — แต่เดิม**ไม่มีอะไรบอกเครื่องว่า
เป็นคนเดียวกัน** ซึ่งเป็นข้อความยืนยันตัวตนที่ Google Knowledge Graph และ AI ต้องการ
เพื่อเชื่อม "ຄຳຫຼ້າ ผู้ชนะในเว็บนี้" เข้ากับบัญชีที่คนติดตามจริง · ลิงก์ถูกกรองด้วย
`safeHttpUrl` ตัวเดียวกับที่กรองลิงก์ที่แสดงบนหน้าเว็บ

หมายเหตุการออกแบบสองข้อ:

- **กรรมการเป็น `ItemList` แยก ไม่ได้ห้อยกับ Event** เพราะ schema.org ไม่มี property
  ชื่อ "judge" บน Event · ถ้าไม่ทำ ระบบจะตอบได้ว่าใครถูกเสนอชื่อ แต่ตอบไม่ได้ว่าใครตัดสิน
- **ผู้ชนะระบุสองที่** (`mainEntity` ของสาขา และ `award` บนตัวคน) เพราะคำถาม
  "สาขานี้ใครชนะ" กับ "คนนี้เคยชนะอะไร" ถามคนละที่และมาถึงคนละหน้า

## 4. คำบรรยายในผลค้นหา

หน้าสาขาที่ประกาศผลแล้วเปลี่ยน `description` จากคำอธิบายสาขา เป็นประโยคที่ตอบคำถามตรงๆ

```
ຄຳຫຼ້າ ສີສຸວັນ ຊະນະສາຂາ ຜູ້ສ້າງສັນແຫ່ງປີ ໃນ ມ່ວນ ອະວອດ 2025
```

คำอธิบายสาขาบอกว่ารางวัลนี้คืออะไร ไม่ได้บอกว่าใครได้ — ผลค้นหาที่มีคำตอบอยู่แล้ว
คือความต่างระหว่างถูกคลิกกับถูกเลื่อนผ่าน

## 5. `llms.txt`

`/llms.txt` — แผนที่เว็บแบบข้อความ **เขียนเป็นภาษาอังกฤษโดยตั้งใจ** ตามธรรมเนียมที่
AI crawler เริ่มอ่าน บอกว่าเว็บนี้คืออะไร · คำตอบแต่ละแบบอยู่หน้าไหน · รูปแบบ URL
(`/awards/<year>/<category-slug>`) · และมีปีไหนเผยแพร่แล้วบ้าง

ไม่มีทางทำให้ request ล้ม — ถ้า API ล่ม รายการปีจะหายไปเฉยๆ แผนที่ที่ขาดถนนหนึ่งเส้น
ดีกว่า 500 บนไฟล์ที่มีไว้ให้อ่าน

## 6. ของที่มีอยู่แล้วก่อนหน้านี้

- `sitemap.xml` ครบทุกปี ทุกสาขา ทุกครีเอเตอร์ (ปีร่างไม่หลุด)
- `robots.txt` ปิด `/admin`
- `canonical` ทุกหน้า — `/awards/latest` ชี้กลับปีจริง ไม่ใช่ตัวเอง
- OG image ทุกหน้า มี fallback เป็นการ์ดแบรนด์ ไม่มีลิงก์ไหนแชร์ออกไปแบบไม่มีรูป
- 301 redirect จาก URL เว็บเก่า
- LCP 588–748ms บน 4G จำลอง — ความเร็วเป็นปัจจัยจัดอันดับ

## 7. ยังไม่ได้ทำ / ต้องใช้คน

| เรื่อง | ใคร |
|---|---|
| **กรอก `nameEn` ให้ครีเอเตอร์และกรรมการ** — ช่องมีแล้ว โครงสร้างส่งไปถึงเครื่องแล้ว (`alternateName`) แต่ถ้าไม่กรอกก็ไม่มีอะไรให้จับตอนถามเป็นภาษาอังกฤษ | ทีม |
| **กรอกคำบรรยาย hero หน้าแรก** — ใช้เป็น `alt` ถ้าเว้นว่างจะ fallback เป็นข้อความกลางๆ | ทีม |
| ส่ง sitemap เข้า Google Search Console หลัง deploy | คุณ |
| ตั้งชื่อไฟล์รูปตอนอัปโหลด (ข้อ 2) — impact ต่ำ ยังไม่ทำ | — |
